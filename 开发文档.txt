1. 项目定义
--------------------------------------------------------------------------------
1.1 一句话
  Stitchcraft 是一个「AI 网站主题生成器」：用户在本机桌面应用里选一个风格主题
  （仓储管理 / 人员管理 / 后勤管理 / 个人空间 / 品牌落地页），用一句话描述需求，
  AI 调用项目内置的模块库与技能包，拼装出一个可预览、可导出、可直接部署的完整
  静态网站。

1.2 用户问题
  - 非技术用户想给业务做一个小型内部系统或展示站，但不会写代码、也不想用重方案。
  - 通用 AI 直接写整站：风格随机、缺少数据交互、没有无障碍/性能底线、每次结果不可控。
  - 现成建站平台：模板固定、数据功能弱、无法接入自己的 AI API、数据只能留在平台。
  Stitchcraft 的回答：把「主题」做成可复用的模块包，把「专家经验」做成内置技能，
  把「AI 入口」交给用户自己配置，把「数据」选择权交给用户（本地或远端）。

1.3 产品目标（v0.2 MVP，本轮交付）
  P0-1 桌面应用启动文件：双击即可启动，打开本地 UI（Edge 应用窗口）。
  P0-2 AI API 配置入口：用户填 provider / base_url / api_key / model，可测试连通。
  P0-3 数据库选择：本地（浏览器 localStorage）或远端（REST / Supabase 兼容），
       录入的 URL 与账户信息在生成时写入生成站点的数据层，供站点直接使用。
  P0-4 风格选项框 + 需求输入框：5 个主题卡片 + 自由输入 + 示例 chip。
  P0-5 AI 生成：把「主题模块 + 技能包 + 用户描述」拼成提示词，产出完整站点文件。
  P0-6 预览 / 导出 ZIP / 项目历史（SQLite 本地库）。
  P0-7 内置技能：modern-web-guidance、GSAP 官方 skills、web-animation-skills，
       生成时自动注入，使输出符合现代 Web 最佳实践并有高质量动效。
  P0-8 演示模式（Mock）：无需任何 API key，使用内置两个成品站演示完整流程。

1.4 非目标（本轮不做）
  - 不做 SaaS 托管、不做多用户/账号系统；应用只在本机运行（127.0.0.1）。
  - 不做自动部署（部署计划在 v0.4，见 8.2）。
  - 不做可视化拖拽编辑器；生成结果为可编辑的 HTML/CSS/JS 文件。
  - 不内置任何 AI 密钥；不向任何第三方发送用户密钥（只发往用户配置的 endpoint）。
  - 不承诺生成结果可商用免审；默认输出 MIT 许可的项目文件，第三方资源按第 6 章。

1.5 成功标准（本轮）
  - 在无网络、无 API key 的机器上，双击启动 → 选主题 → 生成 → 预览 → 导出全流程可用。
  - 配置真实 OpenAI 兼容 key 后，可生成一个与主题匹配、包含可交互数据 CRUD 的站点。
  - `stitch validate --strict` 0 错误 0 警告；单元测试全绿；CI 绿灯。
  - GitHub Pages 展示页可访问（Kiroween 要求的可运行应用 URL 占位）。
  - Devpost 提交 checklist 全部勾选（视频由作者录制）。

3. 产品设计
--------------------------------------------------------------------------------
3.1 目标用户
  - 小店主/团队负责人：要一个库存/排班/物流的简易内部面板。
  - 创作者：要一个放文章和照片的个人空间。
  - 独立开发者：想用自己的 AI API 快速起一个可交付的静态站点。

3.2 端到端流程（桌面应用内 7 步）
  Step 1 启动：双击「启动 Stitchcraft.bat」→ 本地服务启动 → Edge 应用窗口打开。
  Step 2 AI 设置：选择服务商（OpenAI/DeepSeek/OpenRouter/Ollama/自定义）→ 填
         Base URL、API Key、模型名、温度 → 点「测试连接」。
  Step 3 数据库：选「本地」或「远端」；远端填写数据库 URL、账户/anon key、表前缀
         → 点「测试连接」。此配置会写进生成站点的 data-config.js。
  Step 4 选风格：5 张主题卡片（仓储管理/人员管理/后勤管理/个人空间/品牌落地页）。
  Step 5 写需求：一句话或一段话描述网站；可选标题；提供示例 chip。
  Step 6 生成：右侧 9 阶段进度动画 + 日志；完成后切到预览 tab。
  Step 7 结果：预览、另存新窗口、导出 ZIP、在历史记录中回看/删除。

3.3 桌面应用形态（已确认）
  - 形态：本地 Web UI + Microsoft Edge 应用窗口（--app 模式，无地址栏，像原生应用）。
  - 启动文件：`启动 Stitchcraft.bat`（Windows 双击）→ `python -m stitchcraft app`
    → 自动选空闲端口（默认 8765）→ 启动本地 HTTP 服务 → 打开 Edge 应用窗口。
  - 兜底：找不到 Edge 时用默认浏览器打开；控制台打印 URL 方便手动访问。
  - 为什么不用 Electron：零依赖、仓库轻、离线可跑、演示成本低；后端/前端可平移到
    Electron/Tauri 而不改业务逻辑（见 4.3 分层）。

3.4 功能清单
  P0（本轮必须）
    F1 启动器与本地服务
    F2 AI 配置 + 连接测试（密钥本地保存，页面只显示 has_key / key_hint）
    F3 数据库本地/远端配置 + 连接测试 + 配置内嵌生成站点
    F4 主题卡片列表（含示例标记）与主题详情
    F5 需求输入框、示例、标题
    F6 生成任务：9 阶段进度、日志、取消/超时提示（超时按 HTTP 超时处理）
    F7 预览 iframe、新窗口打开、导出 ZIP
    F8 项目历史（SQLite）、删除
    F9 Mock 演示模式（两个内置成品站）
    F10 错误处理：无 key、连不上、AI 返回非法 JSON、文件安全校验
  P1（有空就做）
    F11 生成结果再编辑（打开文件夹/复制路径）
    F12 主题收藏与最近使用
    F13 生成参数高级项（温度、文件数量上限）
  P2（路线图）
    F14 deploy 适配器（Cloudflare Pages/Vercel/Netlify/GitHub Pages）
    F15 MCP server（让 Kiro 直接调用 Stitchcraft 主题与生成能力）
    F16 多语言 UI（中/英）

3.5 AI API 配置设计
  - 统一 OpenAI 兼容协议：POST {base_url}/chat/completions。
  - 预设：OpenAI / DeepSeek / OpenRouter / Ollama（本地 11434）/ Custom。
  - 字段：provider、base_url、model、temperature、api_key。
  - 测试：优先 GET {base_url}/models；失败则发一条 "reply pong" 的最小对话。
  - 存储：%LOCALAPPDATA%\Stitchcraft\config.json（权限尽量 600，永不入仓库）。
  - 生成时若 json_mode 被端点拒绝（400/422），自动降级重试一次普通模式并本地解析 JSON。

3.6 数据库：本地 / 远端（按用户确认的需求）
  - 含义：数据库地址与账户是「生成网站时使用」的配置，不是 Stitchcraft 自身的项目库。
  - 本地模式：生成站点用浏览器 localStorage（键前缀 stitchcraft:），首次打开自动
    种入示例数据；可离线、可 file:// 直接打开。
  - 远端模式：生成站点以 REST 方式访问用户填写的数据库：
      * Supabase 兼容：`${url}/rest/v1/${tablePrefix}_<table>`，请求头 apikey +
        Authorization: Bearer <anonKey>；GET/POST/PATCH/DELETE 语义见第 4.7 节。
      * 通用 REST：GET {url} 可达即视为连接成功；表路径按前缀约定。
  - 配置注入：生成器总是写 `data-config.js`：
      window.STITCHCRAFT_DB = { mode, kind, url, anonKey, tablePrefix };
    并在 index.html 的 </body> 前注入 `<script src="data-config.js"></script>`。
  - 安全：只允许写「公开/anon key」；禁止把 AI 密钥写入生成站点；UI 必须提示。
  - Stitchcraft 自身项目历史始终存本地 SQLite（%LOCALAPPDATA%\Stitchcraft\projects\
    projects.sqlite3），与远端数据库无关。

3.7 风格主题与模块库
  - 5 个主题：warehouse-ops（仓储）、staff-directory（人员）、logistics-control（后勤）、
    personal-space（个人空间）、brand-launch（品牌落地页）。
  - 每个主题 = 一个数据包（见第 5 章）：theme.toml + SKILL.md + data-model.json +
    可选 sample/ 成品站。
  - 共享区块库 themes/_blocks/：hero、stat-grid、data-table、crud-modal、article-list、
    photo-masonry、timeline、cta-band，供 AI 参考拼装。
  - 两个成品站：warehouse-ops/sample 与 personal-space/sample，满足 Skeleton Crew
    「一个骨架 + 两个应用」的要求，也作为 Mock 模式输出。

3.8 生成流水线（UI 上展示 9 个阶段）
  1 Brief          读需求、确定站点标题与目标
  2 Structure      站点结构、页面/区块规划（来自主题 SKILL.md）
  3 Design tokens  颜色/字体/间距（主题 accent + Modern Web Guidance）
  4 Data layer     本地或远端数据库配置与适配器
  5 Hero & layout  首屏与版式
  6 Components     表格/表单/卡片等组件
  7 Motion         GSAP 动效（尊重 prefers-reduced-motion）
  8 Accessibility  WCAG 2.2 AA 检查（标题/alt/viewport/reduced-motion 等启发式）
  9 QA & package   文件安全校验、写盘、打包、生成摘要
  真实 AI 模式：1-7 为提示词装配阶段，第 6 阶段末执行一次模型调用；8-9 为校验与写盘。
  演示模式：按阶段逐步推进动画，复制主题 sample 或生成占位站，不调用模型。

3.9 预览 / 导出 / 历史
  - 预览：GET /api/preview/<project_id>/ 由本地服务器托管生成目录（禁止目录穿越）。
  - 导出：GET /api/export/<project_id> 生成 ZIP（内存打包）。
  - 历史：GET /api/projects；点击回看预览；DELETE 删除项目与磁盘目录。

3.10 演示模式（Mock）
  - 目的：评委/用户无 API key 也能体验完整产品；视频录制零成本可重录。
  - 行为：engine=mock 时复制主题 sample（或占位站），同样写 data-config.js，
    UI 明确标注「Demo output」；远端数据库配置在 AI 模式下才真正生效（UI 文案说明）。

4. 技术方案
--------------------------------------------------------------------------------
4.1 架构总览
  [Edge app window]
        | HTTP/JSON (127.0.0.1:8765)
  [app/web 单页 UI: HTML/CSS/JS + 本地 GSAP]
        |
  [src/stitchcraft/server.py  ThreadingHTTPServer]
        |-- settings.py    读取/保存本地配置（AI、DB、UI）
        |-- ai_client.py   OpenAI 兼容 /chat/completions（urllib，无 SDK）
        |-- storage.py     SQLite 项目库 + 远端数据库连通性测试
        |-- themes.py      主题发现/校验/数据模型
        |-- skills.py      技能注册表 + 提示词上下文拼装
        |-- generator.py   mock/AI 生成引擎（9 阶段、文件安全、写盘）
        |-- desktop.py     启动器（找 Edge、起服务、开窗口）
        |
  [data/ 运行时] %LOCALAPPDATA%\Stitchcraft\config.json + projects\<id>\site\
  [repo 数据] pipeline/ contracts/ modules/ themes/ skills/ .kiro/ app/ docs/

4.2 技术选型与理由
  - Python 3.11+ 标准库：零依赖、任何机器可跑、CI 简单、契合命令行与桌面双形态。
  - HTTP 服务用 http.server.ThreadingHTTPServer：够用、无依赖、可绑定 127.0.0.1。
  - UI 用原生 HTML/CSS/JS：无构建步骤、加载快、易演示、方便被 AI 生成。
  - 动效用官方 GSAP 3.13（本地 vendored）：专业级动画、离线可用。
  - 数据用 SQLite：单文件、事务、零配置；远端数据库只服务于生成站点。
  - 为什么不用 FastAPI/Electron/React：依赖多、构建慢、离线演示风险高；
    评审看重「能跑 + 清楚 + 有 Kiro 治理」，不是技术堆叠。

  Stitchcraft/

  ├─ README.md                    产品说明 + 快速开始 + 黑客松信息

  ├─ pyproject.toml               打包与 stitch 命令入口

4.5 前端组件（app/web）

    日志」三 tab + 历史抽屉。
  - 状态：app.js 单一状态对象；fetch 轮询 /api/jobs/<id> 每 800ms；localStorage 记住
    最近主题与标题。
  - 视觉：Kiroween 万圣节风（深墨 #0e0c12、余烬橙 #ff8a3d、紫 #8b5cf6），
    字体用系统栈，动效用本地 gsap.min.js；尊重 prefers-reduced-motion。
  - 可访问性：语义化标签、label、focus-visible、aria-live 日志、Esc 关闭弹层。

4.6 本地 HTTP API 契约
  GET  /api/status              -> {version, demo_mode, config_path, edge}
  GET  /api/settings            -> 配置（密钥仅 has_key/key_hint）
  POST /api/settings            -> {ok, config_path}
  POST /api/ai/test             -> {ok, message, latency_ms}
  POST /api/db/test             -> {ok, message}
  GET  /api/themes              -> {themes:[{id,name,category,summary,tags,accent,
                                   has_sample,blocks,skills}]}
  GET  /api/skills              -> {skills:[{id,name,category,source,license,summary,
                                   enabled,stages}]}
  POST /api/generate            -> {job_id}  body: {theme_id,title,prompt,engine,
                                   database:{mode,remote:{kind,url,anon_key,table_prefix}}}
  GET  /api/jobs/<job_id>       -> {id,status,stage,stage_name,progress,stages,logs,
                                   project_id,error}
  GET  /api/projects            -> {projects:[...]}
  DELETE /api/projects/<id>     -> {ok}
  GET  /api/preview/<id>/[...]  -> 生成站点静态文件
  GET  /api/demo/<theme_id>/    -> 主题示例站（仅 has_sample 主题）
  GET  /api/export/<id>         -> ZIP 下载
  服务只绑定 127.0.0.1；POST body 上限 2MB；所有用户输入做路径与长度校验。

4.7 生成引擎细节
  - 请求校验：主题存在、需求 ≥ 8 字符、远端模式必须有 URL、AI 模式必须有 key
    （Ollama 例外）。
  - 提示词结构（AI 模式）：
      system = 角色 + 输出 JSON 契约 + 10 条硬规则（离线静态/数据层/无障碍/响应式/
               动效/安全/示例数据/文件完整性等）
      user   = 站点标题 + 用户需求 + 主题说明 + 主题 SKILL.md + data-model.json +
               注入技能上下文（Modern Web Guidance / GSAP / web-animation / house）+
               window.STITCHCRAFT_DB 配置
  - 输出契约：{"files":[{"path","content"}...],"summary":"..."}；仅允许相对路径与白名单扩展名。
  - 失败处理：网络错误/超时/HTTP 非 2xx → 友好错误；JSON 非法 → 报错并提示换模型；
    缺 index.html → 报错；空文件 → 报错；超限 → 报错。
  - 远端数据适配器（写进生成站点 app.js）：
      GET    ${url}/rest/v1/${prefix}_<table>?select=*
      POST   ${url}/rest/v1/${prefix}_<table>   Prefer: return=representation
      PATCH  ${url}/rest/v1/${prefix}_<table>?id=eq.<id>
      DELETE ${url}/rest/v1/${prefix}_<table>?id=eq.<id>
      请求头 apikey / Authorization: Bearer <anonKey>；失败降级到缓存并提示。

4.8 安全与隐私
  - 密钥只存本地配置文件；API GET /api/settings 永不返回明文密钥。
  - 生成站点只写入用户明确配置的远端 URL 与 anon key；提示「不要使用 service key」。
  - 服务仅监听 127.0.0.1，不对外网开放；无 CORS 放宽。
  - 生成文件路径白名单 + 防目录穿越（拒绝 ..、绝对路径）。
  - 日志不打印密钥；错误信息截断。
  - 第三方技能包保留 LICENSE，见 skills/ATTRIBUTION.md。

4.9 依赖与兼容
  - 运行时：Python ≥ 3.11（tomllib）、Edge 或任意现代浏览器、Windows 10/11
    （macOS/Linux 也可用 python -m stitchcraft app + 默认浏览器）。
  - 开发：无 Node 依赖；可选 Node 仅用于 node --check 校验前端 JS。
  - 网络：生成需要能访问用户配置的 AI endpoint；无网时 Mock 模式完整可用。

  guidelines、awesome-copilot premium-frontend-ui、motion.dev skills。

6.2 vendor 规范
  - 原样复制上游文件，不改内容；每个包根目录必须有 LICENSE + UPSTREAM.md
    （仓库 URL、commit SHA、协议、复制范围、日期）。
  - 统一在 skills/ATTRIBUTION.md 汇总；不在 vendor 目录里手改。
  - 更新流程：重新下载 zipball → 替换 → 更新 UPSTREAM/ATTRIBUTION/registry →
    `python -m stitchcraft skills verify` + `python -m stitchcraft validate --strict`。

6.3 skills/registry.toml 格式
  [meta] version/description
  [[skills]] id,name,category,source,license,path,summary,stages,enabled,budget_chars,kind
  kind=skill（有 SKILL.md，可注入）/ kind=asset（如 gsap-lib，只供文件复制）。
  主题通过 theme.toml 的 skills 数组选技能；生成器按 enabled + budget 拼上下文。

6.4 运行时注入策略
  - 默认总预算 24000~26000 字符；每技能单独 budget_chars（如 modern-web-guidance 14000、
    gsap-core 5000）；超预算截断并标注。
  - 注入顺序：主题技能 → GSAP 核心/ScrollTrigger → web-animation → house skills。
  - 注入内容含来源与协议标注，便于审查与署名。
  - 生成站点的 GSAP 使用：提示词告知「./vendor/gsap.min.js 已提供」，生成器在站点引用
    该文件时自动复制 vendored 构建，保证离线可跑。

6.5 House 技能（自制）
  - stitchcraft-data-app：CRUD 数据界面 + 本地/远端适配器契约 + 无障碍/安全要求。
  - stitchcraft-personal-space：个人空间编辑风、文章/照片数据模型、克制动效。

6.6 验证
  - skills/registry.toml 每个 path 存在且 kind=skill 时有 SKILL.md；vendor 包有 LICENSE。
  - CI 执行 `python -m stitchcraft skills verify`。

9.3 手工验收（演示前一遍）
  - 断网双击 bat → UI 打开 → mock 生成 → 预览 → 导出 ZIP。
  - 填真实 key → 测试连接 → AI 生成 → 数据 CRUD 可用 → 导出。
  - 远端数据库配置 → 生成站 data-config.js 内容正确、请求头正确（可看 DevTools）。
  - Edge 窗口 1440×900、390 宽度（DevTools 模拟）无横向滚动。

10. 风险与对策
--------------------------------------------------------------------------------
  R1 GitHub 网络不稳定（已遇到）→ 推送走 ssh.github.com:443；文档/README 用
     raw.githubusercontent 或 gh-proxy 访问；CI 在 GitHub 侧不受影响。
  R2 用户 AI endpoint 不可达/超时/限流 → 友好错误提示、重试一次、建议换模型；
     Mock 模式保证演示不翻车。
  R3 API 费用/额度 → 生成前提示 token 预估；提供「演示模式」；单次生成限制文件与
     长度；默认温度 0.7。
  R4 生成质量不稳定 → 主题 SKILL.md 写死结构、输出契约校验、技能注入、示例数据要求、
     QA 阶段启发式检查；必要时给出「重新生成」按钮。
  R5 密钥泄漏 → 只存本地、GET 掩码、不写日志、不写生成站点、提交前 grep 检查。
  R6 Devpost「可运行应用 URL」→ GitHub Pages 静态展示页（UI + 两个示例站）作为 URL；
     视频中演示本地真实生成；提交说明中注明「桌面应用，本地运行」。
  R7 视频/时间风险 → 脚本先行（hackathon/video-script.md），Mock 模式可重复录制；
     把长任务拆成可独立验证的小步，每天可回滚。
  R8 版权/商标 → 所有 vendor 技能带 LICENSE + UPSTREAM；ATTRIBUTION.md 声明 GSAP、
     Chrome、Kiro 商标归属；不使用未授权素材。
  R9 团队/资格 → 单人项目，避免多设备协作；提交前核对官方规则与地区限制。
